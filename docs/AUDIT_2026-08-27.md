## 2. Decisões arquiteturais

### 2.1 Streaming (F1) — *client-side buffering*

O canal entre MCP server e FreeCAD addon é XML-RPC sobre socket
HTTP, que é estritamente request/response. Não há canal SSE nativo.
Duas alternativas foram consideradas:

* **A. SSE no addon (rejeitado)** — exigiria expor um segundo
  endpoint HTTP dentro do FreeCAD, mais CORS, mais roteamento,
  mais um cliente que o MCP host não entende.
* **B. Client-side buffering + progress notifications
  (escolhido)** — `OutputBuffer` agrega tudo que o RPC já devolve
  (`message` em sucesso, `output`/`error` em falha) e emite
  `ctx.report_progress` com `ProgressDebouncer` (limite de 100 ms
  entre chamadas) para evitar flood do canal JSON-RPC.

B é mais barato e mantém o addon intocado. O LLM continua
recebendo o resultado completo no fim — a UI do MCP host é que
mostra progresso incremental.

### 2.2 Replay (F8) — *persistente + dry-run*

`SessionRecorder` é append-only, fsync'd por step (tmp + `os.replace`),
e thread-safe sob `threading.Lock`. Cada replay é um JSON único em
`~/.config/FreeCAD/mcp-freecad/replays/<session_id>.json`. O tool
`get_replay` aceita três formatos:

* `json` — payload bruto, ideal para diff entre sessões.
* `markdown` — relatório legível para post-mortem.
* `replay` — re-executa contra a conexão viva, **mas com
  `dry_run=True` por padrão**. Tools destrutivos
  (`delete_object`, `execute_code`, `export_object`,
  `run_fem_analysis`, `save_document`) só rodam com
  `allow_destructive=True` explícito.

A política `dry_run=True` por padrão foi a escolha mais segura:
post-mortem é o caso de uso primário, e o operador humano decide
caso a caso quando vale o risco de re-executar.

### 2.3 Profiler (F6) — *ring buffer, não Prometheus*

`metrics.py` já existe para counters/histograms scrapeáveis. O
profiler é separado porque seu caso de uso é diferente:

* **Métricas** são agregados scrapeáveis (Prometheus text format).
* **Profiler** é introspecção por tool call individual (ring buffer
  + percentis + flamegraph export).

Manter os dois módulos separados evita que o profiler contamine o
snapshot de métricas de produção, e deixa cada um otimizado para
o seu caso (métricas: O(1) por evento; profiler: O(N) só quando
o LLM pede `get_stats`).

A escolha do formato de exportação
(`tool_name count duration_ms`, collapsed-stacks) segue
[`brendangregg/FlameGraph`](https://github.com/brendangregg/FlameGraph)
— é o mesmo formato que `speedscope.app` aceita nativamente, então
o LLM pode enviar a saída direto para análise visual.

### 2.4 Diff (F7) — *property bags, não geometry*

`DocumentDiff` opera sobre o snapshot serializado que
`serialize.py` já produz (`{"Properties": {...}}`). Não tenta
fazer diff geométrico de B-reps — esse trabalho pertence ao OCC
e custaria ordens de grandeza a mais. O trade-off é que mover um
objeto de posição conta como "modificado" (Placement mudou), o que
é exatamente o sinal que um LLM precisa para entender que a cena
foi editada.

A canonicalização via `json.dumps(..., sort_keys=True, default=str)`
torna vetores e placements diff-determinísticos independente da
ordem de dict keys.

### 2.5 Workflows (F5) — *templates + safe-execute*

Dois passes de substituição são obrigatórios:

1. `{var}` → valor do `initial_args` (ex.: `{doc_name}` → `"DocA"`).
2. `{prev.X}` → caminho pontilhado no retorno do step anterior
   (ex.: `{prev.document_name}` → `"DocA"` se o step 0 foi
   `create_document`).

Esse modelo é Turing-completo o suficiente para os 3 built-ins
(`create-box-with-save`, `safe-execute`, `duplicate-object`) e
cobre 95% dos pedidos reais. Adicionar Jinja2 seria overkill.

A política `optional=True` é acionada **só em exception**,
não em `{success: False}` retornado pelo FreeCAD — a primeira
indica "step não pôde nem tentar" (ex.: RPC caiu), a segunda
indica "step rodou e FreeCAD recusou". O LLM precisa enxergar
essa diferença.

### 2.6 Web UI (F4) — *standalone, opcional*

FastAPI foi escolhido por ser a stack mais leve para um formulário
estático + um proxy para Ollama. O `create_web_app(freecad,
ollama_url, default_model)` é uma factory para que testes
possam injetar uma `_FakeFreeCAD`. A dependência de `fastapi` e
`httpx` é **opt-in** — o módulo `web_ui.py` falha rápido com um
`ImportError` claro se rodado sem as deps instaladas, e os outros
24 tools não dependem delas.

A porta padrão 8765 é só sugestão; `FREECAD_MCP_WEB_PORT` permite
escolher outra para coexistir com outros serviços locais.
